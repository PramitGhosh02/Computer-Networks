PACKET ANALYSIS USING WIRESHARK
Comprehensive Lab Theory and Execution Guide
Computer Networks Laboratory

1. THEORY AND OBJECTIVE
Packet analysis is the process of capturing and inspecting network
traffic to observe protocol behavior across all layers of the OSI model.
Every packet undergoing network transmission is encapsulated with
headers at each respective layer:

- Application Layer (Layer 7): HTTP, DNS payload data
- Transport Layer (Layer 4): TCP, UDP ports, sequence and ack numbers
- Network Layer (Layer 3): IPv4 source and destination addresses, TTL
- Data Link Layer (Layer 2): Ethernet II MAC addresses
- Physical Layer (Layer 1): Raw transmission media bits

2. PROTOCOLS ANALYZED
1. HTTP (HyperText Transfer Protocol - Application Layer):
   Client-server web request-response protocol over TCP port 80.
   Displays HTTP GET methods, host headers, and 200 OK responses.

2. DNS (Domain Name System - Application Layer):
   Translates domain names to IP addresses over UDP port 53.

3. TCP (Transmission Control Protocol - Transport Layer):
   Connection-oriented reliable transport.
   Demonstrates the Three-Way Handshake:
   - Step 1: Client sends SYN
   - Step 2: Server sends SYN-ACK
   - Step 3: Client sends ACK

4. UDP (User Datagram Protocol - Transport Layer):
   Connectionless, lightweight transport with a fixed 8-byte header
   (Source Port, Destination Port, Length, Checksum).

5. ARP (Address Resolution Protocol - Data Link Layer):
   Resolves IP addresses to hardware MAC addresses on the local network.
   ARP Request is broadcast (MAC ff:ff:ff:ff:ff:ff).
   ARP Reply is unicast directly to requester.

6. ICMP (Internet Control Message Protocol - Network Layer):
   Used for network testing (Ping).
   Type 8: Echo Request.
   Type 0: Echo Reply.

3. STEP-BY-STEP EXECUTION
Step 1: Install required networking tools:
  sudo apt update
  sudo apt install wireshark curl dnsutils net-tools traceroute -y

Step 2: Start Wireshark capture:
  sudo wireshark &
  Double-click eth0 to begin live capture.

Step 3: Generate traffic using the script:
  cd ~/Desktop/CN\ LAB/Packet\ analysis\ using\ a\ packet\ tracer\ tool/
  chmod +x generate_traffic.sh
  ./generate_traffic.sh

Step 4: Stop capture by clicking the Red Square button in Wireshark.

4. WIRESHARK DISPLAY FILTERS
Note: Do not type filter names in the terminal. Type them into the
Wireshark Display Filter bar at the top of the Wireshark window:

- HTTP filter: http
- TCP handshake filter: tcp.flags.syn == 1
- UDP filter: udp
- DNS filter: dns
- ARP filter: arp
- ICMP (Ping) filter: icmp

5. VIVA QUESTIONS
Q1: What are the differences between TCP and UDP headers?
A1: TCP has a variable header (minimum 20 bytes) with sequence numbers,
    acknowledgment numbers, window size, and control flags.
    UDP has a fixed 8-byte header with only 4 fields.

Q2: Why is ARP needed when IP addresses exist?
A2: IP addresses handle routing across logical networks (Layer 3),
    while physical Ethernet cards on a local network deliver data
    using 48-bit MAC addresses (Layer 2). ARP maps IP to MAC.

Q3: What is the TCP Three-Way Handshake?
A3: SYN from client, SYN-ACK from server, ACK from client.
