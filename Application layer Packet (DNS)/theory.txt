ANALYSIS OF APPLICATION LAYER PACKET (DNS)
Comprehensive Lab Theory, Execution and Troubleshooting Guide
Computer Networks Laboratory

1. THEORY AND OBJECTIVE
DNS (Domain Name System) is an Application Layer (Layer 7) protocol
that translates human-readable domain names (like google.com) into
machine-routable numerical IP addresses.

Key Characteristics:
- Protocol Layer: Application Layer (Layer 7)
- Transport Port: Port 53
- Transport Type: UDP for standard queries (fast, lightweight)
                 TCP for zone transfers and replies exceeding 512 bytes
- Architecture: Hierarchical and distributed database
- Caching: Relies on Time-To-Live (TTL) values to reduce latency

2. DNS RECORD TYPES ANALYZED
1. A Record (IPv4 Address):
   Maps domain name to 32-bit IPv4 address.
   Example: google.com resolves to 192.178.174.100.
   Multiple A records provide DNS Load Balancing across servers.

2. AAAA Record (IPv6 Address):
   Maps domain name to 128-bit IPv6 address.
   Example: google.com resolves to 2404:6800:4007:80f::200e.

3. MX Record (Mail Exchange):
   Specifies the mail server responsible for receiving emails for the domain.
   Includes a priority value (lower number indicates higher preference).
   Example: 10 smtp.google.com.

4. SOA Record (Start of Authority):
   Contains administrative details of the DNS zone:
   - origin: Primary master nameserver (ns1.google.com)
   - mail addr: Domain administrator email (dns-admin.google.com)
   - serial: Version number of zone file
   - refresh: Interval secondary servers query primary (900 seconds)
   - retry: Delay before retrying failed refresh (900 seconds)
   - expire: Limit secondary can serve zone data if primary unreachable (1800 seconds)
   - minimum: Negative cache TTL (60 seconds)

5. NS Record (Name Server):
   Lists authoritative nameservers for the domain (ns1 to ns4.google.com).

6. PTR Record (Reverse DNS):
   Resolves IP address back to canonical domain name.

3. STEP-BY-STEP EXECUTION WALKTHROUGH
Step 1: Install DNS utilities in Ubuntu terminal:
  sudo apt update && sudo apt install dnsutils -y

Step 2: Run the automated DNS script:
  cd ~/Desktop/CN\ LAB/Application\ layer\ Packet\ \(DNS\)/
  chmod +x dns.sh
  ./dns.sh

Step 3: Individual manual commands to demonstrate to examiner:
  Basic A record lookup: nslookup google.com
  Query A record via dig: dig google.com A
  Query MX records: dig google.com MX
  Query SOA records: dig google.com SOA
  Query NS records: dig google.com NS +short
  Reverse lookup (PTR): nslookup 192.178.174.138

4. WIRESHARK LIVE PACKET CAPTURE
Step 1: Launch Wireshark:
  sudo wireshark &

Step 2: Double-click eth0 to begin capturing.

Step 3: Type dns in the filter bar and press Enter.

Step 4: In terminal, generate DNS traffic:
  dig google.com MX

Step 5: Click the Red Square button to stop capture.

Step 6: Inspect packet layers in middle pane:
  - Frame: Physical layer timing and packet length
  - Ethernet II: MAC source and destination addresses
  - Internet Protocol: Source IP and Destination IP
  - User Datagram Protocol: Port 53, length, and checksum
  - Domain Name System: Transaction ID, Query Flags (QR=0 query, QR=1 response),
    Question section, and Answer section

5. VIVA QUESTIONS
Q1: Which OSI layer does DNS belong to?
A1: Application Layer (Layer 7).

Q2: Why does DNS primarily use UDP instead of TCP?
A2: DNS queries are small (under 512 bytes) and require low latency.
    UDP eliminates connection setup delay.

Q3: When does DNS use TCP?
A3: For DNS Zone Transfers and when response payloads exceed 512 bytes.

Q4: What is an MX record?
A4: Mail Exchange record specifies the mail server that handles emails
    for the domain, along with an integer priority ranking.
