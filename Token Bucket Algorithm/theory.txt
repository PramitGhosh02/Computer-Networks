TOKEN BUCKET ALGORITHM - Theory and Working
Computer Networks Laboratory

1. THEORY
The Token Bucket Algorithm is a traffic shaping algorithm that allows
short bursts of traffic while enforcing a strict average transmission
rate limit.

Key Principles:
- Tokens are deposited into the bucket at a constant rate.
- The bucket has a finite maximum token capacity.
- Each packet transmitted consumes one token from the bucket.
- If sufficient tokens are available, packets are transmitted immediately
  (allowing bursts up to the available token count).
- If tokens are insufficient, non-conforming packets are dropped.
- Idle time allows tokens to accumulate for future burst demands.

2. WORKING (Step-by-Step)
Step 1: Input the token bucket capacity and token generation rate.
Step 2: Input the number of time intervals and packet sizes for each interval.
Step 3: At each tick:
  - Add tokens at the fixed generation rate (capped at capacity).
  - If incoming packets <= available tokens:
      * Transmit all incoming packets.
      * Deduct tokens consumed.
  - If incoming packets > available tokens:
      * Transmit packets equal to available tokens.
      * Drop the remaining packets.
      * Set remaining tokens to 0.

4. VIVA QUESTIONS
Q1: What is the main difference between Leaky Bucket and Token Bucket?
A1: Leaky Bucket produces a strictly constant output rate and disallows
    bursts. Token Bucket allows controlled bursts up to the number of
    accumulated tokens.
