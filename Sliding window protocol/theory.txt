SLIDING WINDOW PROTOCOL - Theory and Working
Computer Networks Laboratory

1. THEORY
The Sliding Window Protocol is a flow control and error control
protocol used at the Data Link Layer (Layer 2) and Transport Layer
(Layer 4 - TCP) to ensure reliable in-order transmission of frames.

Key Characteristics:
- Window Size (W): Specifies the maximum number of data frames the
  sender can transmit before waiting for an acknowledgment (ACK).
- Sliding Action: Once an acknowledgment is received for the frames
  in the current window, the window boundaries slide forward over
  the remaining frames.
- Stop-and-Wait vs Sliding Window: Stop-and-Wait sends 1 frame and
  idles until an ACK arrives (very low bandwidth utilization).
  Sliding Window transmits multiple frames concurrently up to window
  capacity, greatly improving throughput.

2. WORKING (Step-by-Step)
Step 1: Input the window size (W).
Step 2: Input the total number of frames (N).
Step 3: Input the frame values.
Step 4: Transmit frames in chunks equal to the window size.
Step 5: Receive acknowledgments for the transmitted frames.
Step 6: Slide the window forward to the next set of frames.
Step 7: Repeat until all frames have been sent and acknowledged.

4. VIVA QUESTIONS
Q1: What is the main purpose of the Sliding Window Protocol?
A1: Flow control (preventing a fast sender from overwhelming a slow
    receiver) and error control through acknowledgments.

Q2: What are the two main types of Sliding Window Protocol?
A2: Go-Back-N and Selective Repeat.
