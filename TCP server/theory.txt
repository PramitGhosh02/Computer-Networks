TCP SERVER - Theory and Working
Computer Networks Laboratory

1. THEORY
TCP (Transmission Control Protocol) is a connection-oriented
protocol operating at the Transport Layer (Layer 4) of the
OSI model. It provides reliable, ordered, and error-checked
delivery of data between applications.

Key characteristics of TCP:
- Connection-oriented: requires handshake before data transfer.
- Reliable delivery: guarantees all data reaches destination.
- Flow control: prevents sender from overwhelming receiver.
- Congestion control: adapts to network traffic conditions.
- Full-duplex: data flows in both directions simultaneously.
- Byte-stream oriented: treats data as a continuous stream.

TCP Three-Way Handshake (Connection Establishment):
1. Client to Server: SYN (synchronize)
2. Server to Client: SYN-ACK (synchronize + acknowledge)
3. Client to Server: ACK (acknowledge)

TCP Four-Way Handshake (Connection Termination):
1. Client to Server: FIN
2. Server to Client: ACK
3. Server to Client: FIN
4. Client to Server: ACK

TCP Server Responsibilities:
- Listens on a specified port for incoming client connections.
- Accepts client connection requests.
- Continuously receives messages from the connected client.
- Sends acknowledgments or replies back to the client.

2. SOCKET API FUNCTIONS USED
- socket(): Creates a communication endpoint.
  Parameters: AF_INET (IPv4), SOCK_STREAM (TCP), protocol 0.
- setsockopt(): Configures socket options (SO_REUSEADDR prevents
  "Address already in use" errors on server restarts).
- bind(): Associates the socket with a local IP address and port number.
- listen(): Puts the socket in passive listening mode with a backlog queue.
- accept(): Blocks until a client connects, returning a new dedicated
  socket descriptor for communication with that client.
- read(): Reads incoming data from the client socket buffer.
- send(): Transmits data back to the client.
- close(): Closes the socket descriptors and releases resources.

3. WORKING (Step-by-Step)
Step 1: Create a TCP socket using socket(AF_INET, SOCK_STREAM, 0).
Step 2: Set SO_REUSEADDR option using setsockopt().
Step 3: Configure server address: AF_INET, INADDR_ANY, and port (htons(8080)).
Step 4: Bind the socket to the port using bind().
Step 5: Listen for connections using listen().
Step 6: Accept incoming client connection using accept().
Step 7: Continuous communication loop:
  - Read message from client using read().
  - Print received client message.
  - Send acknowledgment response using send().
  - If client sends "exit" or disconnects, break loop.
Step 8: Close client and server sockets using close().

4. HOW TO COMPILE AND RUN (Ubuntu Terminal)
Step 1: Open terminal and navigate to directory:
  cd ~/Desktop/CN\ LAB/TCP\ server/

Step 2: Compile the server program:
  gcc tcp_server.c -o tcp_server

Step 3: Run the server:
  ./tcp_server

Step 4: In a second terminal, run the client:
  cd ~/Desktop/CN\ LAB/TCP\ client/
  gcc tcp_client.c -o tcp_client
  ./tcp_client

5. RUNNING ON TWO DIFFERENT COMPUTERS (LAN / Wi-Fi)
Step 1: On Server computer, find its IP address:
  hostname -I
  (Example: 192.168.1.15)

Step 2: Allow port in Ubuntu firewall if needed:
  sudo ufw allow 8080/tcp

Step 3: Start server on Server computer:
  ./tcp_server

Step 4: On Client computer, run client with Server's IP:
  ./tcp_client 192.168.1.15

Note: No code change is needed in tcp_server.c because INADDR_ANY
binds to all available network interfaces.
