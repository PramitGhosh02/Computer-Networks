1. THEORY
============================================================

TCP (Transmission Control Protocol) is a connection-oriented
protocol operating at the Transport Layer (Layer 4) of the
OSI model. It provides reliable, ordered, and error-checked
delivery of data between applications.

Key characteristics of TCP:
  - Connection-oriented (requires handshake before data transfer)
  - Reliable delivery (guarantees all data reaches destination)
  - Flow control (prevents sender from overwhelming receiver)
  - Congestion control (adapts to network conditions)
  - Full-duplex communication (data flows in both directions)
  - Byte-stream oriented (treats data as a continuous stream)

TCP uses a THREE-WAY HANDSHAKE to establish a connection:
  1. Client → Server : SYN (synchronize)
  2. Server → Client : SYN-ACK (synchronize + acknowledge)
  3. Client → Server : ACK (acknowledge)

TCP uses a FOUR-WAY HANDSHAKE to terminate a connection:
  1. Client → Server : FIN
  2. Server → Client : ACK
  3. Server → Client : FIN
  4. Client → Server : ACK

A TCP Server is a program that:
  - Listens on a specific port for incoming connections
  - Accepts client connections
  - Receives and processes client requests
  - Sends responses back to clients


2. SOCKET API FUNCTIONS USED
============================================================

  socket()  → Creates a new communication endpoint (socket)
              Parameters: domain (AF_INET for IPv4),
              type (SOCK_STREAM for TCP), protocol (0)

  bind()    → Assigns an address (IP + port) to the socket
              Binds the server to a specific port so clients
              know where to connect

  listen()  → Marks the socket as passive (ready to accept)
              The backlog parameter sets the queue size for
              pending connections

  accept()  → Extracts the first connection from the queue
              Blocks until a client connects
              Returns a NEW socket for the specific client

  read()    → Receives data from the connected client

  send()    → Sends data back to the connected client

  close()   → Closes the socket and frees resources


3. WORKING (Step-by-Step)
============================================================

  Step 1: CREATE SOCKET
    - socket(AF_INET, SOCK_STREAM, 0)
    - Creates a TCP socket (SOCK_STREAM = TCP)
    - Returns a file descriptor (integer) for the socket

  Step 2: CONFIGURE ADDRESS
    - Set sin_family = AF_INET (IPv4)
    - Set sin_addr = INADDR_ANY (accept from any interface)
    - Set sin_port = htons(8080) (convert to network byte order)

  Step 3: BIND
    - bind(server_fd, address, size)
    - Associates the socket with port 8080
    - Only one process can bind to a port at a time

  Step 4: LISTEN
    - listen(server_fd, 3)
    - Server enters passive mode, waiting for connections
    - Backlog = 3 means up to 3 pending connections queued

  Step 5: ACCEPT
    - new_socket = accept(server_fd, ...)
    - Blocks (waits) until a client connects
    - Returns a NEW socket dedicated to that client
    - The original socket continues listening

  Step 6: RECEIVE DATA
    - read(new_socket, buffer, size)
    - Reads the message sent by the client into buffer

  Step 7: SEND RESPONSE
    - send(new_socket, response, length, 0)
    - Sends the response string back to the client

  Step 8: CLOSE
    - close(new_socket) — close client connection
    - close(server_fd)  — close the listening socket

5. KEY CONCEPTS
============================================================

  PORT NUMBER:
    - A 16-bit number (0-65535) identifying a service
    - Well-known ports: 0-1023 (HTTP=80, FTP=21, SSH=22)
    - Registered ports: 1024-49151
    - Dynamic ports: 49152-65535

  htons() (Host TO Network Short):
    - Converts port number from host byte order to
      network byte order (big-endian)
    - Required because different machines may store
      bytes in different orders

  INADDR_ANY:
    - Tells the server to accept connections on ANY
      network interface (WiFi, Ethernet, loopback, etc.)

  SOCK_STREAM:
    - Socket type for TCP (stream-oriented)
    - Contrast with SOCK_DGRAM for UDP (datagram-oriented)

============================================================
   HOW TO RUN (Ubuntu Terminal)
============================================================

  Step 1: Open a terminal and navigate to the folder:
    $ cd ~/Desktop/CN\ LAB/TCP\ server/

  Step 2: Compile the program:
    $ gcc tcp_server.c -o tcp_server

  Step 3: Run the server:
    $ ./tcp_server

  Step 4: Open a SECOND terminal and test with a client:
    $ echo "Hello from client!" | nc localhost 8080

    OR compile and run the TCP client program:
    $ cd ~/Desktop/CN\ LAB/TCP\ client/
    $ gcc tcp_client.c -o tcp_client
    $ ./tcp_client

  Note: The server must be running BEFORE the client connects.
  Note: If port 8080 is busy, change PORT in the code and
        recompile.
