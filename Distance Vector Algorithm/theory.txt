1. THEORY
============================================================

The Distance Vector Routing Algorithm is a dynamic routing
algorithm used in computer networks where each router
maintains a table (vector) of minimum distances to every
other router and updates it by exchanging information with
its directly connected neighbors.

It is based on the Bellman-Ford Algorithm.

Bellman-Ford Equation:
  D(x,y) = min { cost(x,v) + D(v,y) }
            for all neighbors v of x

  Where:
    D(x,y)    = shortest distance from x to y
    cost(x,v) = direct link cost from x to neighbor v
    D(v,y)    = distance from neighbor v to destination y

Key characteristics:
  - Each router knows only its NEIGHBORS and their costs
  - Routers share their distance vectors with neighbors
  - Iterative: repeats until no changes (convergence)
  - Distributed: each router computes independently
  - Asynchronous: routers don't need to update simultaneously

Used in:
  - RIP (Routing Information Protocol)
  - BGP (Border Gateway Protocol, uses path vectors)
  - IGRP (Interior Gateway Routing Protocol, Cisco)


2. ALGORITHM
============================================================

  INITIALIZATION:
    For each router x:
      For each destination y:
        if y is a neighbor:
          D(x,y) = direct link cost
          next_hop(x,y) = y
        else if x == y:
          D(x,y) = 0
        else:
          D(x,y) = INFINITY (unreachable)

  ITERATION (repeat until convergence):
    For each router x:
      For each destination y:
        For each neighbor v of x:
          new_cost = cost(x,v) + D(v,y)
          if new_cost < D(x,y):
            D(x,y) = new_cost        ← shorter path found!
            next_hop(x,y) = v        ← route through v
            updated = true

  CONVERGENCE:
    When no router updates its table in an iteration,
    the algorithm has CONVERGED — all routes are optimal.


3. WORKING (Step-by-Step)
============================================================

  Example Network (4 nodes):

        1         3
  (0)-------(1)-------(3)
    \       /
   4 \     / 2
      \   /
       (2)

  Cost Matrix:
          Node 0  Node 1  Node 2  Node 3
  Node 0:   0       1       4       INF
  Node 1:   1       0       2       3
  Node 2:   4       2       0       INF
  Node 3:   INF     3       INF     0

  INITIAL DISTANCE TABLES (each router knows only neighbors):

  Router 0: {0→0:0, 0→1:1, 0→2:4, 0→3:INF}
  Router 1: {1→0:1, 1→1:0, 1→2:2, 1→3:3}
  Router 2: {2→0:4, 2→1:2, 2→2:0, 2→3:INF}
  Router 3: {3→0:INF, 3→1:3, 3→2:INF, 3→3:0}

  ITERATION 1 (exchange and update):

  Router 0 checks via neighbor 1:
    0→3 via 1: cost(0,1) + D(1,3) = 1 + 3 = 4 < INF ✓ UPDATE!
    0→2 via 1: cost(0,1) + D(1,2) = 1 + 2 = 3 < 4   ✓ UPDATE!

  Router 2 checks via neighbor 1:
    2→3 via 1: cost(2,1) + D(1,3) = 2 + 3 = 5 < INF ✓ UPDATE!
    2→0 via 1: cost(2,1) + D(1,0) = 2 + 1 = 3 < 4   ✓ UPDATE!

  Router 3 checks via neighbor 1:
    3→0 via 1: cost(3,1) + D(1,0) = 3 + 1 = 4 < INF ✓ UPDATE!
    3→2 via 1: cost(3,1) + D(1,2) = 3 + 2 = 5 < INF ✓ UPDATE!

  AFTER ITERATION 1:
  Router 0: {0:0, 1:1, 2:3(via1), 3:4(via1)}
  Router 1: {0:1, 1:0, 2:2, 3:3}
  Router 2: {0:3(via1), 1:2, 2:0, 3:5(via1)}
  Router 3: {0:4(via1), 1:3, 2:5(via1), 3:0}

  ITERATION 2:
  No changes → CONVERGED!

5. KEY CONCEPTS
============================================================

  CONVERGENCE:
    - The state when all routers have consistent, optimal tables
    - No more updates needed
    - Time to converge depends on network size and topology

  COUNT TO INFINITY PROBLEM:
    - When a link fails, routers may slowly increment distances
    - Example: If link breaks, routers keep adding costs
      through each other, counting up toward infinity
    - Solutions:
      a) Split Horizon: Don't advertise route back to source
      b) Poison Reverse: Advertise failed route as INFINITY
      c) Maximum hop count: RIP limits to 15 hops (16 = INF)
      d) Hold-down timers: Ignore updates for failed routes

  DISTANCE VECTOR vs LINK STATE:
    ┌──────────────────┬──────────────────┬──────────────────┐
    │ Feature          │ Distance Vector  │ Link State       │
    ├──────────────────┼──────────────────┼──────────────────┤
    │ Algorithm        │ Bellman-Ford     │ Dijkstra's       │
    │ Knowledge        │ Neighbors only   │ Entire topology  │
    │ Updates sent     │ Full table to    │ Link info to     │
    │                  │ neighbors        │ ALL routers      │
    │ Convergence      │ Slow             │ Fast             │
    │ Memory           │ Less             │ More             │
    │ Loop-free        │ No (count to ∞)  │ Yes              │
    │ Protocol example │ RIP, IGRP       │ OSPF, IS-IS      │
    │ Complexity       │ Simple           │ Complex          │
    └──────────────────┴──────────────────┴──────────────────┘

  RIP (Routing Information Protocol):
    - Uses Distance Vector algorithm
    - Metric: Hop count (max 15, 16 = unreachable)
    - Updates: Every 30 seconds (broadcast full table)
    - Convergence: Slow
    - Used in: Small networks

  BELLMAN-FORD PROPERTIES:
    - Time complexity: O(V × E) where V=vertices, E=edges
    - Can handle negative edge weights (unlike Dijkstra)
    - Detects negative cycles
    - Converges in at most V-1 iterations

          1
    (0)-------(1)
      \       /
     3 \     / 2
        \   /
         (2)

    Cost from Node 0 to Node 0: 0

    Cost from Node 1 to Node 2: 2

    Cost from Node 2 to Node 0: 3

    - Shows the initial cost matrix
    - Shows initial distance tables for each router
    - Iterates until convergence:
        Node 0: Shorter path to 2 found via 1 (old=3, new=3)

  Note: Enter 9999 (not 0) for nodes that are NOT directly
        connected to each other.
